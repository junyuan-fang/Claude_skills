# 用户画像

## 偏好风格
- 要求全程静默执行，不发任何中间态/收尾状态消息，只推送实际内容
- 完成后只用一句话汇报关键结果（文件路径、篇数、刷新状态）；纯推送类任务连收尾汇报也不要
- 内容要求尽调式深度扩展，每条带公司背景+数据+业内对比，让不熟悉领域的人 30 秒理解 why-it-matters
- 反感只堆关键词、并列符堆砌；偏好口语化+具体数字（x 倍、y 亿、z 万）
- 已熟知的领域概念（VLA、WAM、Sim2Real、Diffusion Policy、VLM、RL、Imitation Learning、Whole-body Control、ZMP、MPC 等）不要再解释
- 概念解释的判断标准：谷歌一搜有 Wikipedia 条目的概念一律不解释，只解释新方法/数据集/内部代号类新生术语
- 一句话汇报里习惯附带笔记行数与团队署名等可核验细节（如"412 行/华为诺亚"），并说明被跳过的论文及原因
- 接受"判断后不执行"的汇报：同日重复触发且无新增信源时，跳过重发并说明理由（避免重复内容+加深节流）优于机械执行
- 接受后台 agent 异步完成任务后的补充确认汇报（如笔记行数校验通过、索引数稳定、无遗留项）

## 注意事项
- 图片一次性发送，失败不重试、不补文字（会触发节流升级）
- sleep 30 不能省略，否则短窗口节流
- 论文日期必须硬校验，宁可放弃论文项也不把老论文包装成"今日新发"
- 每日重新搜索去重，不能照抄前一天内容；同日重复触发先查归档，已推送且无新增信源就不重发
- 目录页刷新（概念数+论文数）是流水线必要收尾，双 vault 需同步；最后一次同步无新增文件时应明确说明索引已稳定
- 三类故障均会导致定时任务失败：401 OAuth 失效、本地 API ConnectionRefused、账号用量限额——恢复后需留意补漏并排查
- 用量限额在 08:30 (Asia/Shanghai) 重置，被拦截的任务可在重置后或次个工作日补跑
- 静默推送任务的空响应属正常（无收尾消息即成功），但需与 API Error / limit 报错区分——靠归档文件/推送内容判断实际执行结果
- 周末/节假日 arXiv 无新论文属常态，推荐可多为再推复用，不必强凑新笔记
- 07:00 NVIDIA 任务超时（>10 分钟）是后续任务被限额挤掉的先行信号，可据此提前压缩当日工作量
- 两档新闻任务间隔仅 45 分钟，NVIDIA 档超时会直接压缩具身智能档窗口，需控制单档搜索深度
- 长耗时笔记生成可交给后台 agent 并行，全部回执后需核对行数、确认与主汇总一致并声明无待办
