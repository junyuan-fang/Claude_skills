# cc-send-safe 微信推送防节流协议

## 适用场景

任何一次任务里需要经 `cc-send-safe` 向微信通道发送 **多条文字或图片** 时（日报、摘要、批量结果推送）。

## 发送节奏

1. 单次任务最多 3 次推送：文字 → 文字 → 图片。
2. 每两次推送之间 **必须 `sleep 30`**，连发会触发短窗口节流。
3. 单条文字控制在 700-800 字符以内。

```bash
cc-send-safe -m "<第 1 段>"
sleep 30
cc-send-safe -m "<第 2 段>"
sleep 30
cc-send-safe --image /tmp/xxx.jpg
```

## 图片规则

4. 一次任务只准备并发送 **1 张** 图片（第 3 张必触发节流锁死）。
5. 发送前先验证：`file /tmp/xxx.jpg` 确认是图片；若 >100KB 用 `convert` 压到 ≤80KB JPEG。
6. 图片发送 **一次性，失败即放弃，绝不重试** —— 每次失败请求都会加深节流。
7. 图片失败后 **不要再发任何文字**（包括说明失败的文字），会触发节流升级。

## 静默原则

8. 不发任何中间态 / 收尾状态消息：「段X已发」「任务完成」「已推送…」「归档在 XX 路径」全部禁止。用户只想看实际内容，状态信息是噪音，也白白消耗推送配额。
9. 需要确认结果时只写本地 stdout 日志（如 `ls -la <归档目录> | tail -5`），不发到推送通道。

## 注意

- 图片失败时不必解释，用户能从内容缺失自行判断。
- 若通道已长时间返回 ret=-2，说明已被锁死，停止一切发送，等待冷却而不是重试。
