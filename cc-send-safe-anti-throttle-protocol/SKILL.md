# cc-send-safe 推送防节流发送协议

## 何时用 / 适用场景

任何一轮任务需要通过 `cc-send-safe` 向 cc-connect（微信/飞书）通道推送 **多条消息**（多段文字 + 图片）时：每日新闻、日报、周报、摘要、长内容分段、批量结果推送等。

cc-connect 通道对短窗口内连发和失败重试都极其敏感，触发 ret=-2 后会锁死通道一段时间，且 **每次失败请求都会加深节流等级**。

## 硬规则（固定发送节奏）

1. **单轮任务最多 3 次推送**：文字 → 文字 → 图片（**2 段文字 + 1 张图片**）。总推送次数 ≤ 3。
2. **每两次推送之间必须 `sleep 30`**，不得省略、不得缩短——连发会触发短窗口节流。
3. 单条文字控制在 **700–800 字符**以内。
4. **文字分段衔接**：第 1 段末尾标注「(深度细节见第 2 段)」，让用户知道还有后续。
5. **一次任务最多 1 张图片**。第 2 张有风险，第 3 次图片请求必触发节流锁死。
6. 图片 **一次性尝试，失败即放弃，绝不重试**：每次失败请求都会加深节流惩罚。
7. 图片失败后 **不要再发任何文字**（包括「图片发送失败」这类解释、道歉、状态说明），会触发节流升级。用户能从内容缺失自行判断，无需告知。

## 典型发送序列

```bash
cc-send-safe -m "<第 1 段全文>（深度细节见第 2 段）"
sleep 30
cc-send-safe -m "<第 2 段全文>"
sleep 30
cc-send-safe --image /tmp/<name>.jpg    # 一次性尝试，失败即止
```

## 图片准备与规则

8. 一次任务（每轮）只准备并发送 **1 张** 图片。
9. 图片下载到固定路径 `/tmp/<name>.jpg`（如 `/tmp/xxx_daily.jpg`）。
10. 发送前先验证类型并压缩：

```bash
file /tmp/<name>.jpg                     # 确认确实是图片而非 HTML 错误页
convert /tmp/<name>.jpg -quality 75 -resize 1200x /tmp/<name>.jpg   # >100KB 时压到 ≤80KB JPEG
```

   压到 75 质量 / 1200 宽仍 >80KB 时，再降一档：

```bash
convert /tmp/<name>.jpg -quality 70 -resize 1024x /tmp/<name>.jpg
```

## 静默原则

11. **不发任何中间态 / 收尾状态消息**：「段 X 已发」「任务完成」「已推送…」「归档写到 XX 路径」全部禁止。状态信息对用户是纯噪音，且额外占用推送配额、加深节流；只推送实际内容。
12. 需要确认结果 / 自检的本地信息（归档文件列表等）只写本地 stdout 日志，不发到推送通道，例如：

```bash
ls -la /home/xinmiao/code/claude_bot/news_archive/ | tail -5
```

## 绝对禁止

- 省略或缩短 `sleep 30` 直接连发
- 单任务发 2 张及以上图片
- 图片失败后重试图片
- 图片失败后补发文字
- 推送任何中间态 / 收尾状态消息

## 注意

- 若通道已长时间返回 ret=-2，说明已被锁死，停止一切发送，等待冷却而不是重试。
