# 论文流水线静默运行 + 一句话汇报

## 步骤

1. 用户说「今日论文推荐」/「过去 N 天论文推荐」时，**直接进入 `daily-papers` 总入口**，不要逐步征询确认、不要先问要不要跑。
2. 顺序执行三步流水线，中途**不发任何中间状态消息**（不报「抓取完成」「第 1 步完成」「正在抓取」「开始打分」「正在生成笔记」，也不发中间产物路径）：
   - **fetch**：调用 `daily-papers-fetch` — 抓 arXiv + HuggingFace 最新论文，打分筛选、富化，输出 `/tmp/daily_papers_enriched.json`。
   - **review**：调用 `daily-papers-review` — 读富化数据 + 扫描 Obsidian 笔记库，生成有态度的推荐点评，写入推荐文件 `/home/xinmiao/code/claude_bot/Obsidian_Vault/DailyPapers/$(date +%F)-论文推荐.md`，并更新 history。git 自动化保持关闭。
   - **notes**：调用 `daily-papers-notes` — 为「必读」档论文补概念库并生成完整笔记，链接回填到推荐文件，刷新目录页（概念 MOC / 论文 MOC）。git 自动化保持关闭。
3. **三步之间有严格数据依赖，必须串行执行，不能把 fetch/review/notes 三步并行。**
4. 单步内部的笔记生成可用后台 agent 并行跑；**必须等每个 agent 回报并核对行数/校验结果**，确认无遗留项后才收尾。
5. 支持多天模式：「过去 3 天论文推荐」「过去一周的论文」「最近 5 天」等，把天数参数透传给 fetch 步骤。
6. 全部完成后，只输出**一句话**汇报，必须包含三要素：
   - 推荐文件绝对路径（如 `/home/xinmiao/code/claude_bot/Obsidian_Vault/DailyPapers/YYYY-MM-DD-论文推荐.md`），可附分档「N 篇，x 必读 / y 值得看 / z 可跳过」
   - 重点论文笔记生成篇数
   - 目录页是否刷新（概念 MOC 更新 X 篇、论文 MOC 是否同步 Y 篇）
7. 若当日无新 robotics 必读（HF Trending 多为 LLM/T2I 跨界、arXiv API 超时等），笔记数可为 0，但仍要诚实在这一句话中说明原因。

## 一句话模板

`推荐文件 \`<绝对路径>\`（N 篇，x 必读 / y 值得看 / z 可跳过 — <可选原因说明>，已笔记 M 篇），目录页已刷新（概念 MOC X 篇、论文 MOC Y 篇）。`

## 笔记质量校验

- 生成的笔记必须包含 `## 关键公式` 与 `## 实验结果` 两个章节，缺失则**补全后再汇报完成**，不要带着缺章节的笔记收尾。
- **后台 agent 的自述不等于事实**：拿到回报后要用行数或文件校验确认笔记确实写盘（例如确认某篇笔记 966 行、校验通过）。
- 汇报前确认推荐文件里的笔记链接已回填、目录页（概念 MOC / 论文 MOC）已刷新，不需要用户再手动改。

## 注意

- **git 自动化默认关闭**，三步全程不要自作主张 commit / push，除非用户明确要求提交。
- 不要在流水线中间输出进度播报（包括「第 1 步完成」之类）；用户明确要求「全程静默」，只要最终一句话结论，任何进度播报都算噪音。
- 整条流水线耗时约 25–30 分钟（实测 ~1780s），静默期不代表不工作，长响应时间属正常；不要中途插话或提前汇报。
- arXiv API 偶发超时是常见现象，HF Trending 是 fallback 源。
- 不要为了凑数把跨界 LLM/T2I 论文硬塞进 robotics 推荐。
- 一句话汇报里可顺带带上分级统计（必读 / 值得看 / 可跳过篇数）和概念库新增条数，但不要展开成多段。
